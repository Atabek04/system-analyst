# Языки высокого уровня скрывают сложность машины

---

## Слайд 1: Построение ещё одного переводчика

**Студенты:** "Значит, нам нужен переводчик для переводчика? Что-то, что конвертирует человеко-подобный код в ассемблер?"

**Преподаватель:** "Точно. И это именно то, что произошло исторически."

---

## Слайд 2: Рождение языков высокого уровня

**Вместо написания этого на ассемблере:**
```
MOV AX, 5
CMP AX, 18
JLE denied
MOV BX, welcome_msg
JMP print
denied:
MOV BX, denied_msg
print:
CALL display
...
```

**Вы пишете это:**
```python
if age > 18:
    print("Добро пожаловать")
else:
    print("Доступ запрещён")
```

**3 строки вместо 15.**

**Никаких адресов памяти. Никаких регистров. Никаких инструкций прыжков.**

**Просто логика, которая имеет смысл для людей.**

---

## Слайд 3: Что переводит это?

**Переводчик для языков высокого уровня имеет название: Компилятор** (или **Интерпретатор**, в зависимости от языка).

**Как это работает:**
1. Вы пишете: `if age > 18: print("Добро пожаловать")`
2. Компилятор конвертирует это в ассемблер: `MOV AX, 5`, `CMP AX, 18`, и т.д.
3. Ассемблер конвертирует ассемблер в машинный код: `00010001 00000101...`
4. Процессор выполняет двоичный код

---

## Слайд 4: Полная цепочка перевода

**Теперь у нас полная картина:**

```
Человек пишет:      if age > 18: print("Добро пожаловать")    (Python/Java)
         ↓
Компилятор:         MOV AX, 5; CMP AX, 18; ...                (Ассемблер)
         ↓
Ассемблер:          00010001 00000101 00000110...             (Машинный код)
         ↓
Процессор выполняет: Двоичные паттерны запускают схемы
```

**Три слоя перевода:**
1. **Компилятор/Интерпретатор** → конвертирует Python/Java в ассемблер
2. **Ассемблер** → конвертирует ассемблер в машинный код
3. **Процессор** → выполняет машинный код

**Каждый слой существует, чтобы сделать слой выше него легче для людей.**

## Слайд 5: Критическая проверка понимания

**Вопрос:**
> Когда вы пишете `print("Добро пожаловать")` на Python и запускаете программу...
>
> В момент, когда процессор выполняет эту инструкцию, что он действительно видит?
>
> A: Слово "print"?
>
> B: Инструкции ассемблера?
>
> C: Двоичные паттерны?

**Студенты:** "Э-э... мы говорили, что процессор читает только двоичный код. Значит C?"

**Преподаватель:** "Совершенно верно."

## Слайд 6: Процессор ничего не знает о Python

**Вот глубокая истина:**

**Процессор понятия не имеет, что Python существует.**

**Когда вы запускаете программу на Python:**
- Python переводится в ассемблер
- Ассемблер переводится в двоичный код
- **Только двоичный код достигает процессора**

**Процессор просто видит паттерны вроде `00010001`, текущие через него.**

**Он не знает:**
- На каком языке вы писали (Python? Java? C++?)
- Как выглядел оригинальный код
- Что вообще был вовлечён человек

**Python, Java, JavaScript — это всё удобства для людей.**

**Процессор говорит только на одном языке: двоичном.**

## Слайд 7: Проверка понимания

**Вопрос 1:**
> Видит ли процессор когда-либо слово "print", когда вы запускаете код на Python?

**Ответ:** Нет. К тому времени, как инструкции достигают процессора, всё — двоичный код. Слово "print" было конвертировано в ассемблер, затем в двоичные паттерны.

**Вопрос 2:**
> Могут ли два разных языка (Python и Java) компилироваться в одни и те же инструкции ассемблера?

**Ответ:** Да. Если Python `print("Привет")` и Java `System.out.println("Привет")` оба приводят к одной и той же операции отображения, компилятор может сгенерировать идентичный ассемблер для обоих.

**Вопрос 3:**
> Зачем нам нужны компиляторы? Почему бы просто не писать на ассемблере напрямую?

**Ответ:** Ассемблер всё ещё слишком низкоуровневый и многословный. Написание `if age > 18` на ассемблере занимает 15+ строк. Языки высокого уровня позволяют людям думать логикой, а не адресами памяти.

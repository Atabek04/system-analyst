### Слайд 2: ВОПРОС — Что такое сервер?
**Студенты говорят "браузер идёт на сервер". Что такое сервер?**

- Это специальное магическое устройство?
- Это что-то совершенно отличное от обычного компьютера?
- Чем сервер отличается от вашего ноутбука?

*Время на размышление: 7-10 секунд*

---

### Слайд 3: ОТВЕТ — Сервер это просто компьютер
**Развенчиваем миф: сервер = обычный компьютер**

- **Сервер** — это обычный компьютер (процессор, RAM, диск — всё как у вас)
- **Ключевое отличие:** работает 24/7 без выключения
- Более мощный: больше процессоров, больше RAM (64-512 GB), больше дисков
- Находится в **дата-центре** (специальное помещение с охлаждением и бесперебойным питанием)
- **Никакой магии** — просто компьютер, который ВСЕГДА включён и ждёт запросы
- Может обслуживать тысячи клиентов одновременно

---

### Слайд 4: ОТВЕТ — Браузер не знает адрес
**Проблема: браузер не знает, ГДЕ сервер**

- Браузер не знает, где находится сервер YouTube
- Нужно кого-то спросить, кто знает ВСЕ адреса в интернете
- Этот "кто-то" называется **DNS** (Domain Name System)
- DNS = телефонная книга интернета

---

### Слайд 5: ВОПРОС — Кто знает все адреса?
**Кто говорит вашему браузеру "Сервер YouTube находится по адресу [конкретный адрес]"?**

*Подсказка: это распределённая база данных, которая переводит имена в адреса*

---

### Слайд 6: ОТВЕТ — DNS (Domain Name System)
**DNS переводит имена → адреса**

- DNS — это массивная распределённая база данных
- **Шаг 1:** Браузер → DNS: "Где 'youtube.com'?"
- **Шаг 2:** DNS → Браузер: "youtube.com = **142.250.80.78**"
- Число 142.250.80.78 называется **IP-адрес** (как домашний адрес для компьютеров)
- **Шаг 3:** Браузер подключается к 142.250.80.78

---

### Слайд 7: ВОПРОС — Сценарий краха DNS
**Представьте: DNS-серверы упали по всему миру. Вы набираете "facebook.com". Что произойдёт?**

- A) Сайт Facebook исчез навсегда
- B) Ошибка — браузер не может найти адрес
- C) Всё работает нормально

*Время на размышление: 7-10 секунд*

### Слайд 8: ОТВЕТ — DNS краш
**Правильный ответ: B) Ошибка — браузер не может найти адрес**

- Серверы Facebook работают идеально
- Браузер просто не может найти адрес для подключения
- **Уточнение:** Если вы знаете IP-адрес (157.240.22.35), можете ввести его напрямую
- DNS не хранит данные — только адреса

### Слайд 10: ОТВЕТ — Ethernet кабель
**Прямое соединение через кабель**

- **Ethernet кабель** (толще телефонного, разъём шире)
- Один конец → Компьютер A
- Другой конец → Компьютер B
- Электрические сигналы через медные провода
- Прямая связь без посредников

### Слайд 12: ОТВЕТ — 3 кабеля

### Слайд 15: ВОПРОС — Решение проблемы

*Подсказка: подумайте об удлинителе с множеством розеток*

---

### Слайд 16: ОТВЕТ — Сетевой свитч
**Свитч = центральное устройство**

- **Сетевой свитч** (network switch)
- Каждый компьютер → ОДИН кабель → свитч
- Свитч умно маршрутизирует сообщения между компьютерами
- 100 компьютеров = 100 кабелей (не 5000!)
- Аналогия: удлинитель с множеством розеток

### Слайд 18: ОТВЕТ — Лимиты кабелей
**Да, Ethernet имеет лимит**

- Стандартный Ethernet: ~100 метров
- После этого сигнал слишком слабый
- Расстояние между городами: 10,000+ метров
- Нужно решение для больших расстояний

### Слайд 21: ВОПРОС — Телефонные кабели vs Интернет
**Телефонные кабели изобретены в 1800-х — до интернета. Что они передавали изначально?**

*Подсказка: оба передают электрические сигналы*

---

### Слайд 22: ОТВЕТ — Один носитель, разные сигналы
**Та же медь, разные паттерны**

- Телефон: сигналы голоса (вибрации звука)
- Интернет: сигналы данных (1 и 0)
- **Ключевой момент:** Тот же физический носитель (медь), разные паттерны сигналов
- Можно использовать старые телефонные линии для интернета

---

### Слайд 23: ВОПРОС — Типы кабелей
**Три типа кабелей для интернета:**
1. Медь (электричество)
2. Оптоволокно (световые импульсы)
3. Коаксиал (ТВ-кабели)

**Какой быстрее и почему?**

*Подсказка: свет vs электричество — что быстрее?*

---

### Слайд 24: ОТВЕТ — Оптоволокно vs Медь
**Скорость одинакова, дальность разная**

- **Скорость:** Свет и электричество ~200,000 км/с (почти одинаково)
- **Ключевое различие:** Свет слабеет медленнее
- Медь: сигнал умирает через ~100 метров
- Оптоволокно: 40+ километров без ослабления
- **Применение:** дом = Ethernet, между городами = оптоволокно

---

### Слайд 26: ОТВЕТ — Репитеры и усилители
**Устройства для усиления сигнала**

- **Репитеры/усилители** каждые ~40-80 км
- Процесс:
  1. Получают слабый сигнал
  2. Читают данные (1 и 0)
  3. Отправляют новый сильный сигнал
- Аналогия: эстафетный бег (бегун передаёт эстафету свежему бегуну)
- Данные "перепрыгивают" 1000+ км через цепочку репитеров

### Слайд 28: ОТВЕТ — Кабель питает репитеры
**Один кабель = данные + питание**

- Кабель выполняет ДВЕ задачи:
  1. Передача данных (световые импульсы в оптоволокне)
  2. Передача электричества (через медные жилы)
- Станции на берегу отправляют высоковольтное питание
- Репитеры усиливают сигнал каждые ~50-100 км
- **Один кабель = данные + энергия для репитеров**

### Слайд 32: ОТВЕТ — Модель ISP
**ISP = владельцы "интернет-шоссе"**

---

### Слайд 34: ОТВЕТ — Конкуренция и регулирование
**Множество ISP = конкуренция**

- **Проблема монополии:** контроль цен, плохой сервис, нет выбора
- **Решение:**
  - Несколько ISP в каждой стране
  - Конкурируют за клиентов (лучшие цены, скорость)
  - Соединяют сети друг с другом (доступ ко всему интернету)
  - Государственное регулирование против монополий

### Слайд 36: ОТВЕТ — Полный путь запроса
**От браузера до Google и обратно**

1. Браузер → DNS-запрос: "Где google.com?"
2. DNS → Ответ: "IP-адрес 142.250.185.46"
3. Браузер → Ethernet кабель → Свитч → ISP кабели
4. ISP сеть → Оптоволокно → Репитеры каждые 40-80 км
5. Достигает сервера Google по IP-адресу
6. Сервер отправляет ответ обратно тем же путём
7. Данные → Свитч → Ваш компьютер → Браузер отображает страницу

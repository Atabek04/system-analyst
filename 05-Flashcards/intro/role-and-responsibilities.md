Coding Questions
Чем занимается System Analyst на проекте?
Back: **System Analyst** — мост между бизнесом и технической командой. Собирает, анализирует и документирует требования, выступает медиатором при конфликтах интересов и следит, чтобы продукт соответствовал реальным потребностям бизнеса.
Tags: intro role
END

START
Coding Questions
Чем System Analyst отличается от Business Analyst?
Back: **SA** фокусируется на технических требованиях и проектировании системы (КАК работает). **BA** — на бизнес-процессах и ценности (ЗАЧЕМ бизнесу это нужно). На практике роли часто пересекаются.
Tags: intro role
END

START
Coding Questions
Кто такой Stakeholder в контексте проекта?
Back: **Stakeholder (заинтересованная сторона)** — любой, кто может повлиять на проект или кого затрагивает его результат: спонсоры, конечные пользователи, руководители, разработчики, регуляторные органы, внешние партнёры.
Tags: intro stakeholder
END

START
Coding Questions
Зачем аналитику вести Stakeholder Register?
Back: **Stakeholder Register (реестр стейкхолдеров)** документирует всех: роль, интересы, уровень власти, требования, риски и стратегию коммуникации. Гарантирует, что ни один ключевой человек не забыт.
Tags: intro stakeholder
END

START
Coding Questions
Что делает SA, когда у двух стейкхолдеров конфликтующие требования?
Back: SA выступает **медиатором**: слушает без осуждения, раскрывает скрытые потребности за высказанными желаниями, предлагает компромисс и документирует решение с обоснованием. Если компромисс невозможен — выносит на уровень стейкхолдеров с высокой властью.
Tags: intro stakeholder mediation
END

Back: **6 ролей**: Product Owner/PM, Developers, QA/Testers, UX/UI Designers, Project Manager, DevOps.

START
Coding Questions
Как Product Owner взаимодействует с System Analyst?
Back: **Product Owner / Product Manager** определяет бизнес-приоритеты и ведёт список задач продукта. SA уточняет его требования и переводит их в технические спецификации.
Tags: intro role hierarchy
END

START
Coding Questions
Как Developers взаимодействуют с System Analyst?
Back: **Developers** реализуют решение. SA объясняет требования, отвечает на вопросы в ходе разработки и проверяет, что реализованное соответствует спецификации.
Tags: intro role hierarchy
END

START
Coding Questions
Как QA/Testers взаимодействуют с System Analyst?
Back: **QA / Testers** проверяют соответствие требованиям. SA предоставляет критерии приёмки (Acceptance Criteria), на основе которых QA пишет тест-кейсы.
Tags: intro role hierarchy
END

START
Coding Questions
Как UX/UI Designers взаимодействуют с System Analyst?
Back: **UX/UI Designers** проектируют пользовательский опыт. SA предоставляет пользовательские требования и сценарии, дизайнеры создают прототипы, SA проверяет соответствие требованиям.
Tags: intro role hierarchy
END

START
Coding Questions
Как Project Manager взаимодействует с System Analyst?
Back: **Project Manager** управляет сроками и ресурсами проекта. SA предоставляет оценки трудозатрат на анализ и документирование требований.
Tags: intro role hierarchy
END

START
Coding Questions
Как DevOps взаимодействует с System Analyst?
Back: **DevOps** отвечает за развёртывание и эксплуатацию системы. SA описывает нефункциональные требования к инфраструктуре: производительность, доступность, среды развёртывания.
Tags: intro role hierarchy
END

- BPMN 2.0, UML, Use Cases / User Stories
- базовый SQL, ER-диаграммы
- коммуникация со стейкхолдерами
- портфолио из 5–7 примеров

Сколько уровней в карьерном пути System Analyst?
Back: **4 уровня**: Junior SA, Middle SA, Senior SA, Специализация.
Tags: intro career
END

START
Coding Questions
Что характеризует Junior SA в карьерном пути?
Back: **Junior SA** (0–1 год) — обучение под наставничеством, работа над частью проекта, освоение инструментов (BPMN, UML, SQL).
Tags: intro career
END

START
Coding Questions
Что характеризует Middle SA в карьерном пути?
Back: **Middle SA** (1–3 года) — самостоятельное ведение проектов, медиация конфликтов стейкхолдеров, уверенное владение инструментами.
Tags: intro career
END

START
Coding Questions
Что характеризует Senior SA в карьерном пути?
Back: **Senior SA** (3+ лет) — участие в архитектурных решениях, менторинг junior-аналитиков, лидерство в требованиях на уровне продукта.
Tags: intro career
END

START
Coding Questions
Какие направления специализации открываются после Senior SA?
Back: Lead/Principal SA, Product Management, Project Management, Consulting. Каждое развивает либо техническую глубину, либо управленческие компетенции.
Tags: intro career
END

Coding Questions
Что такое требование (Requirement) в разработке ПО?
Back: **Requirement** — задокументированное описание того, что система должна делать (функциональное) или как должна работать (нефункциональное), чтобы удовлетворить потребности заинтересованных сторон.
Tags: requirements fundamentals
END

START
Coding Questions
Почему ошибки в требованиях особенно дорого обходятся?
Back: Ошибка на этапе требований разлетается по всем следующим этапам: проектирование, разработка, тестирование — исправление обходится в 10–100 раз дороже, чем если исправить сразу.
Tags: requirements fundamentals
END

START
Coding Questions
Что означает аббревиатура SMART применительно к требованиям?
Back: **SMART** — фреймворк качества требований: 5 критериев, по одному на каждую букву.
Tags: requirements fundamentals smart
END

START
Coding Questions
Что означает буква S в SMART для требований?
Back: **S — Specific (конкретное)**: требование чётко описывает, что нужно, без размытых формулировок.
Tags: requirements fundamentals smart
END

START
Coding Questions
Что означает буква M в SMART для требований?
Back: **M — Measurable (измеримое)**: есть количественный критерий. Пример: «загружается за < 2 секунды».
Tags: requirements fundamentals smart
END

START
Coding Questions
Что означает буква A в SMART для требований?
Back: **A — Achievable (достижимое)**: требование технически и практически выполнимо в рамках проекта.
Tags: requirements fundamentals smart
END

START
Coding Questions
Что означает буква R в SMART для требований?
Back: **R — Relevant (релевантное)**: требование соответствует бизнес-целям и решает реальную проблему.
Tags: requirements fundamentals smart
END

START
Coding Questions
Что означает буква T в SMART для требований?
Back: **T — Time-bound (ограниченное во времени)**: у требования есть дедлайн или привязка к конкретной версии продукта.
Tags: requirements fundamentals smart
END

START
Coding Questions
Сколько уровней в пирамиде требований?
Back: **4 уровня**: Business Requirements, User Requirements, Functional Requirements, Non-Functional Requirements.
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Что такое 1-й уровень пирамиды требований — Business Requirements?
Back: **Business Requirements (BR)** — отвечают на вопрос ЗАЧЕМ. Бизнес-цели верхнего уровня. Пример: «увеличить продажи на 25%».
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Что такое 2-й уровень пирамиды требований — User Requirements?
Back: **User Requirements (UR)** — отвечают на вопрос ЧТО нужно пользователям. Пример: «быстро находить нужный товар».
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Что такое 3-й уровень пирамиды требований — Functional Requirements?
Back: **Functional Requirements (FR)** — отвечают на вопрос КАК система себя ведёт. Пример: «фильтр по ценовому диапазону».
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Что такое 4-й уровень пирамиды требований — Non-Functional Requirements?
Back: **Non-Functional Requirements (NFR)** — атрибуты качества системы. Пример: «страница загружается за < 2 сек».
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Как уровни пирамиды требований связаны между собой?
Back: Каждый уровень прослеживается к вышестоящему: FR выполняет UR → UR достигает BR. Это называется **трассируемостью (Traceability)** требований.
Tags: requirements fundamentals pyramid
END

START
Coding Questions
Сколько типичных последствий влекут плохо определённые требования?
Back: **5 последствий** — от неправильно построенного продукта до провала всего проекта.
Tags: requirements fundamentals
END

START
Coding Questions
Каково 1-е последствие плохо определённых требований?
Back: Разработчики строят не то: исправление потом стоит в 10–100 раз дороже, чем на этапе требований.
Tags: requirements fundamentals
END

START
Coding Questions
Каково 2-е последствие плохо определённых требований?
Back: Тестировщики не знают, что проверять — нет чёткого критерия готовности.
Tags: requirements fundamentals
END

START
Coding Questions
Каково 3-е последствие плохо определённых требований?
Back: Заинтересованные стороны разочарованы результатом: получили не то, что ожидали.
Tags: requirements fundamentals
END

START
Coding Questions
Каково 4-е последствие плохо определённых требований?
Back: **Scope Creep** — бесконтрольное расширение объёма: «что мы имели в виду» никогда не было зафиксировано.
Tags: requirements fundamentals
END

START
Coding Questions
Каково 5-е последствие плохо определённых требований?
Back: Провал проекта — ~70% провалов IT-проектов связаны именно с некачественными требованиями.
Tags: requirements fundamentals
END

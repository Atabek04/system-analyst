Coding Questions
Что такое MVP и что значит "viable"?
Back: **MVP** (Minimum Viable Product) — версия с минимальным набором функций, которая УЖЕ решает проблему пользователя. "Viable" означает работающий продукт, который приносит ценность — не макет. Цель: выпустить быстро, получить обратную связь, итерировать.

Coding Questions
Почему "скейтборд → самокат → велосипед → машина" — правильная аналогия MVP?
Back: На КАЖДОМ этапе пользователь может "ехать" (продукт работает). Неправильный подход — "колесо → шасси → кузов → машина": ничего не работает до самого конца. MVP — простой, но полноценный продукт. Каждая итерация приносит пользу и генерирует обратную связь.

Как связаны MVP и MoSCoW?
Back: **MVP = только Must have из MoSCoW**. Процесс: собрать все User Stories → приоритизировать → взять Must have → это MVP. v2.0 добавляет Should have, v3.0 — Could have. Пример: MVP = Каталог + Корзина + Заказ + Оплата.

Что такое Scope Creep и почему это опасно?
Back: **Scope Creep** — неконтролируемый рост требований в ходе проекта. Признаки: постоянные "маленькие" добавления, "это же быстро!", дедлайны не сдвигаются а работы прибавляется. Опасно: сроки срываются, бюджет превышается, качество падает, команда выгорает.
Tags: requirements scope-creep
<!--ID: 1778007805185-->

Coding Questions
Что такое Baseline в контексте предотвращения Scope Creep?
Back: **1. Baseline (Базовые требования)** — формальная фиксация объёма на старте проекта. Любое отклонение от Baseline — не "маленькое добавление", а изменение с оценкой последствий.

Как Change Request помогает предотвратить Scope Creep?
Back: **2. Change Request Process** — любое новое требование проходит формальный путь: запрос → оценка влияния → одобрение/отклонение → обновление Baseline. Исключает стихийные добавления "по ходу дела".

Как подход "да, но" помогает при Scope Creep?
Back: **3. Подход "да, но"** — вместо отказа: "Мы можем добавить фильтры, но это +2 недели к дедлайну и +N часов бюджета." Стейкхолдер сам принимает осознанное решение.

Как Trade-offs и регулярные обзоры скоупа помогают при Scope Creep?
Back: **4. Trade-offs** — "Фильтры ИЛИ профиль пользователя — что важнее?" Заставляет приоритизировать. **5. Регулярные обзоры скоупа** — напоминают всем, о чём договорились на старте, предотвращают "амнезию" стейкхолдеров.

Что такое Change Request (CR) и из каких шагов состоит процесс?
Back: **Change Request** — формальный запрос на изменение объёма проекта. 4 шага:
1. **Запрос**: ЧТО хотят и ЗАЧЕМ
2. **Оценка**: время, стоимость, риски
3. **Решение**: одобрить / отклонить / отложить
4. **Документирование**: обновить Baseline

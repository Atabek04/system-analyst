Что такое CJM (Customer Journey Map) и из чего она состоит?
Back: **CJM** — визуальная карта всего опыта клиента при взаимодействии с продуктом. Компоненты:
- **Этапы (Stages)** — фазы пути (осведомлённость → рассмотрение → покупка → использование)
- **Действия (Actions)** — что пользователь делает на каждом этапе
- **Touchpoints** — где пользователь "касается" бренда (сайт, приложение, email)
- **Эмоции (Emotions)** — положительные/отрицательные ощущения на каждом шаге
- **Pain Points** — где пользователь испытывает трудности
- **Возможности (Opportunities)** — как улучшить каждую болевую точку

Как CJM помогает системному аналитику находить требования?
Back: CJM → конвейер требований:
1. **Найти Pain Points** (например, "каждый раз вводить адрес")
2. **Определить возможности** (например, "сохранённые адреса")
3. **Написать User Stories** (например, "As a покупатель, I want сохранять адреса, so that не вводить их заново")
4. **Приоритизировать по MoSCoW**
Каждая болевая точка — потенциальная фича. CJM гарантирует, что ты не пропустишь требования, важные для реальных пользователей.

Что такое Трассировка требований (Traceability) и почему это важно?
Back: **Traceability** — отслеживание цепочки связей:
```
Business Req → User Req → Functional Req → Test Cases
```
Почему это важно:
- Ничего не теряется (каждый FR прослеживается до бизнес-цели)
- Понятно ЗАЧЕМ каждое требование
- Легко найти, что ещё не реализовано
- Оценить влияние изменений (если BR меняется, какие FR/тесты затронуты?)

Как выглядит Traceability Matrix (матрица трассировки требований)?
Back: Таблица, связывающая требования по уровням:

| Business | User | FR | Test |
|---|---|---|---|
| BR-001: Продажи +25% | UR-001: Найти товары | FR-001: Фильтр по цене | TC-001: Фильтр работает |
| BR-001: Продажи +25% | UR-002: Добавить в корзину | FR-002: Кнопка корзины | TC-002: Товар в корзине |
| BR-002: Меньше обращений в поддержку | UR-003: Отследить заказ | FR-003: Статус заказа | TC-003: Статус обновляется |

Читай: бизнесу нужны продажи → пользователь должен искать → системе нужен фильтр → проверяется тестом.

Каков полный жизненный цикл требования от идеи до продакшена?
Back:
1. **Сбор (Elicitation)** — собрать у заинтересованных сторон, из CJM, документов
2. **Документирование (Documentation)** — записать как User Stories + Acceptance Criteria
3. **Приоритизация (Prioritization)** — MoSCoW, Kano, определение MVP
4. **Управление (Management)** — Traceability Matrix, Change Requests
5. **Разработка** → **Тестирование** → **Релиз**
6. **Итерация** — добавить Should/Could have в следующих версиях
Роль SA: провести требование от начальной идеи до продакшена.

Coding Questions
Какие основные принципы Kanban?
Back:
1. **Визуализируй работу** — используй доску с колонками (To Do → In Progress → Done)
2. **Ограничивай WIP (Work in Progress)** — установи максимум задач на колонку, чтобы не перегружаться
3. **Управляй потоком (Flow)** — оптимизируй плавное, непрерывное движение задач
4. **Сделай правила явными** — чёткие критерии перехода задач между колонками
5. **Улучшай совместно** — используй данные для постоянного улучшения процесса

Чем Kanban отличается от Scrum?
Back:
- **Scrum** имеет фиксированные Sprint, определённые роли и церемонии; работа планируется на Sprint
- **Kanban** — непрерывный поток, нет фиксированных Sprint, нет предписанных ролей; работа «вытягивается», когда есть свободная ёмкость
- Scrum ограничивает работу по **времени** (Sprint); Kanban — по **WIP-лимитам** (макс. задач в работе)
- Kanban лучше подходит командам с непредсказуемым потоком задач (поддержка, ops); Scrum — для планируемой продуктовой разработки

Что такое WIP-лимит и почему он важен?
Back: **WIP (Work in Progress) лимит** — максимальное количество задач, разрешённых в колонке одновременно. Пример: колонка «In Progress» имеет WIP-лимит 3. Почему это важно:
- Предотвращает многозадачность (которая снижает качество и скорость)
- Выявляет узкие места (Bottleneck) — если колонка постоянно на лимите, есть проблема
- Заставляет команду завершать задачи, прежде чем брать новые

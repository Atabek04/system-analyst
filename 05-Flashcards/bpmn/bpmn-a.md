Coding Questions
Что такое BPMN и зачем он нужен системному аналитику?
Back: **BPMN** (Business Process Model and Notation) — международный стандарт ISO/IEC 19510 для описания бизнес-процессов. Нужен SA, чтобы зафиксировать AS-IS (как работает процесс сейчас) и TO-BE (как должен работать после изменений) — до проектирования технического решения.
Tags: bpmn basics
END

START
Coding Questions
Чем BPMN отличается от UML?
Back: **BPMN** — язык бизнеса: читают аналитик + бизнес, описывает процесс (КТО, ЧТО, КОГДА). **UML** — язык разработчиков: читают архитектор + девелопер, описывает систему (классы, объекты, поведение кода). Оба нужны, но в разное время и для разной аудитории.
Tags: bpmn basics
END

Coding Questions
Что такое Start Event в BPMN и как он выглядит?
Back: **Start Event** — триггер, с которого начинается процесс. Визуально: тонкий круг `○`. Один на процесс (обычно). Название = что запускает процесс. Пример: `○ Заявитель пришёл в ЦОН`.
Tags: bpmn events
END

START
Coding Questions
Что такое End Event в BPMN и как он выглядит?
Back: **End Event** — конкретный исход процесса. Визуально: жирный круг `◉`. Может быть несколько — для разных исходов. Пример: `◉ ВУ выдано`, `◉ Отказ по лишению`.
Tags: bpmn events
END

Coding Questions
Что такое Task в BPMN и каково правило атомарности?
Back: **Task** — одно конкретное действие, прямоугольник со скруглёнными углами. **Правило атомарности**: Task = одно действие, один исполнитель. Тест: если действие можно разбить через "и / или / затем" — это уже несколько Task'ов. Название: глагол + объект.
Tags: bpmn task
END

START
Coding Questions
Что такое Sequence Flow в BPMN?
Back: **Sequence Flow** — сплошная стрелка `→`, задающая порядок выполнения шагов. Утверждает: "после этого — вот это". Правило: каждый элемент (кроме Start и End) имеет входящий и исходящий поток. Всегда односторонняя.
Tags: bpmn flow
END

START
Coding Questions
Чем Sequence Flow отличается от Message Flow?
Back: **Sequence Flow** — сплошная стрелка, только **внутри** одного Pool, задаёт порядок шагов. **Message Flow** — пунктирная стрелка, только **между** Pool'ами, передаёт сообщение другой организации. Сплошная стрелка никогда не пересекает границу Pool.
Tags: bpmn flow
END

Coding Questions
Сколько типов Task существует в BPMN?
Back: 4 типа: User Task (👤), Service Task (⚙), Manual Task (✋), Send/Receive Task (📤📥)
Tags: bpmn task
END

START
Coding Questions
Что такое User Task и когда его использовать?
Back: **User Task** 👤 — человек выполняет работу **через** программу (сайт, CRM, портал). Оба нужны: убери человека — шаг встал. Убери программу — тоже. Тест: "участвует живой человек?" + "он работает через систему?" → оба "да" = User Task.
Tags: bpmn task
END

START
Coding Questions
Что такое Service Task и когда его использовать?
Back: **Service Task** ⚙ — шаг исполняет система **автоматически**, без участия человека. Тест: убери человека — шаг всё ещё работает? → Service Task. Пример: SMS-шлюз отправляет уведомление, система проверяет кредитный рейтинг.
Tags: bpmn task
END

START
Coding Questions
Что такое Manual Task и когда его использовать?
Back: **Manual Task** ✋ — человек выполняет действие **без ИТ**, чисто физически. Тест: есть ли экран перед исполнителем в момент действия? Нет → Manual Task. Пример: курьер доставляет права, кассир принимает наличные, врач проводит осмотр.
Tags: bpmn task
END

START
Coding Questions
Чем Send Task отличается от Receive Task?
Back: **Send Task** 📤 — отправить сообщение и **сразу продолжить** процесс, не ожидая ответа. **Receive Task** 📥 — процесс **блокируется** и продолжается только после получения ответного сообщения. Разница = ждёт ли процесс ответа.
Tags: bpmn task
END

START
Coding Questions
Чем Service Task отличается от Send/Receive Task?
Back: **Service Task** ⚙ — вызвал и получил ответ **мгновенно** (синхронно, как HTTP-запрос). **Send/Receive** 📤📥 — отправил сообщение, процесс **встаёт на паузу** и ждёт ответа неизвестно сколько (асинхронно). Ключевой признак: процесс ждёт → Send/Receive.
Tags: bpmn task
END

Coding Questions
Что такое уровни детализации в BPMN и как выбирать нужный?
Back: **High-level** — для руководства (одна задача "Проверить документы"). **Detailed** — для аналитиков/разработчиков (каждая проверка отдельно). **Implementation** — для технарей (+ системы, API, таймауты). Инструмент детализации: Collapsed Sub-Process. Правило: начни с high-level, детализируй только там, где решение зависит от деталей.
Tags: bpmn basics
END

Coding Questions
Сколько типов Gateway (шлюз) существует в BPMN?
Back: 4 типа: XOR (Exclusive) `◇×`, AND (Parallel) `◇+`, OR (Inclusive) `◇○`, Event-based `◇⌖`
Tags: bpmn gateway
END

START
Coding Questions
Что такое XOR Gateway и когда его использовать?
Back: **XOR Gateway** `◇×` — выбирает ровно ОДНУ ветку по условию на данных. Условия взаимоисключающие. Пример: "медсправка действительна?" → да: продолжить; нет: на медкомиссию. Все исходящие ветки должны быть подписаны условием.
Tags: bpmn gateway
END

START
Coding Questions
Что такое AND Gateway и как он работает?
Back: **AND Gateway** `◇+` — запускает ВСЕ ветки одновременно. Используется парой: split (разветвление) + join (схождение). Join ждёт, пока завершатся ВСЕ ветки. Пример: параллельная проверка базы нарушений + оформление пошлины + запрос справки.
Tags: bpmn gateway
END

START
Coding Questions
Что такое OR Gateway и чем он отличается от XOR?
Back: **OR Gateway** `◇○` — выбирает одну ИЛИ несколько веток, чьи условия истинны. Join ждёт только реально запущенные ветки. XOR → ровно одна ветка. OR → минимум одна, может несколько. Пример: уведомить по email, SMS, Telegram — в зависимости от указанных контактов.
Tags: bpmn gateway
END

START
Coding Questions
Что такое Event-based Gateway и чем он отличается от XOR?
Back: **Event-based Gateway** `◇⌖` — выбор по тому, **какое событие наступит первым**. Каждая ветка начинается с события (не задачи). XOR проверяет условие на данных; Event-based ждёт событие. Пример: вызов на табло vs таймаут 1 час — срабатывает то, что произошло раньше.
Tags: bpmn gateway
END

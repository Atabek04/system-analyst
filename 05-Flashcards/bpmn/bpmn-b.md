Coding Questions
Что такое Pool в BPMN?
Back: **Pool** — "бассейн", граница одной организации или одного процесса. Один Pool = один участник процесса (компания, система). Всё, что снаружи — чужая организация, чужой Pool. Sequence Flow не пересекает границу Pool.
Tags: bpmn pool
END

Coding Questions
Что такое Lane (дорожка) в BPMN?
Back: **Lane** — "дорожка в бассейне", разделение Pool по ролям, отделам или системам. Отвечает на вопрос КТО выполняет задачи. Lane описывает роль, а не конкретного человека: "Регистратор", "QA", "CRM". Каждая задача лежит строго в одной дорожке.
Tags: bpmn pool
END

START
Coding Questions
Как решить: Lane или отдельный Pool?
Back: Тест: "если я позвоню директору и скажу 'сделай иначе' — он послушает?" Да → одна организация → Lane. Нет → разные организации → отдельный Pool. Правило: Lane = внутренние роли; Pool = внешняя организация или неконтролируемая система.
Tags: bpmn pool
END

Coding Questions
Что такое Message Flow и когда его использовать?
Back: **Message Flow** — пунктирная стрелка с кружком, соединяет ТОЛЬКО разные Pool'ы. Передаёт сообщение от одной организации к другой. Sequence Flow (сплошная) — только внутри одного Pool. Правило: сплошная стрелка никогда не пересекает границу Pool.
Tags: bpmn pool flow
END

Coding Questions
Что такое "чёрный ящик" (Black Box Pool) в BPMN?
Back: **Black Box Pool** — Pool внешней организации без внутреннего содержимого. Фиксирует факт обмена сообщениями, но не описывает внутренний процесс. Используется, когда внутреннее устройство нас не касается. Пример: Pool «Платёжный шлюз» или «Медлаборатория».
Tags: bpmn pool
END

Coding Questions
Что такое Sub-process в BPMN?
Back: **Sub-process** — задача-папка `[+]` с полноценным внутренним процессом. Снаружи — один прямоугольник, внутри — своя диаграмма со Start/End/Tasks/Gateways. Используется, чтобы скрыть сложность, не теряя деталей. Аналог: функция с вложенной логикой.
Tags: bpmn artifacts
END

Coding Questions
Чем Sub-process отличается от Group в BPMN?
Back: **Sub-process** `[+]` — функциональная единица с внутренним процессом; влияет на исполнение. **Group** — пунктирная рамка вокруг логически связанных шагов, только визуальная; не влияет на исполнение и может пересекать дорожки.
Tags: bpmn artifacts
END

Coding Questions
Что такое Loop marker в BPMN?
Back: **Loop marker** `↻` — значок повтора под задачей или Sub-process. Обозначает, что элемент может выполняться повторно. Заменяет рисование явной обратной стрелки. Условие повтора пишется рядом. Пример: "Сдача экзамена ↻ (до 3 попыток)".
Tags: bpmn artifacts
END

Что такое Data Object в BPMN?
Back: **Data Object** 📄 — данные, с которыми работают задачи (бумага, файл, JSON). Соединяется с задачей пунктирной ассоциацией. Живёт только внутри одного экземпляра процесса. НЕ управляет потоком — только сопровождает. IT-аналог: JSON в теле запроса.
Tags: bpmn artifacts
END

START
Coding Questions
Чем Data Store отличается от Data Object?
Back: **Data Object** 📄 — одноразовый артефакт, живёт внутри конкретного экземпляра процесса. **Data Store** 🗄 — постоянное хранилище, "переживает" процесс (база данных, реестр). IT-аналог: Data Object — JSON в памяти; Data Store — PostgreSQL, S3-бакет.
Tags: bpmn artifacts
END

Coding Questions
Что такое Annotation (аннотация) в BPMN?
Back: **Annotation** — комментарий для читателя, квадратная скобка `[ ... ]` с текстом, прикреплённая ассоциацией. Движок процессов её игнорирует — на исполнение не влияет. Использовать, когда правило неочевидно из названия элемента.
Tags: bpmn artifacts
END

Что такое AS-IS и TO-BE диаграммы в BPMN?
Back: **AS-IS** — как процесс работает СЕЙЧАС (фиксация текущего состояния). **TO-BE** — как процесс должен работать ПОСЛЕ изменений (целевое состояние). SA сначала рисует AS-IS → выявляет проблемы → проектирует TO-BE. Это не "плохой/хороший", а "до/после".
Tags: bpmn basics
END

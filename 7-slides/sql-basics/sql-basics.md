# Таблица = Класс. Строка = Объект.

<!-- VISUAL: Два блока рядом. Слева — Class Diagram: прямоугольник "User" с атрибутами name, email, age. Справа — SQL-таблица с заголовком столбцов (id, name, email, age) и 3 строками данных. Стрелка между ними с подписью "одно и то же". -->

- **Таблица (Table)** — структура хранения, как класс в UML
- **Столбец (Column)** — атрибут класса (`name`, `email`)
- **Строка (Row)** — конкретный объект / экземпляр (`Алексей, alex@mail.ru`)
- **Ячейка (Cell)** — одно конкретное значение (`"Алексей"`)

<!--

- Нарисуй на доске: класс User → таблица users → строки с реальными людьми
- Предсказуемый вопрос: "А где база данных физически?" → "На сервере — это файлы на диске, только умно организованные."
- ~5 мин

# Пример: Class Diagram vs SQL Таблица

| id | name    | email              | age |

| 1  | Алексей | alex@mail.ru       | 28  |
| 2  | Мария   | maria@gmail.com    | 24  |

- Класс `User` описывает **что хранить**

- Первичный ключ **(Primary Key)** `id` — уникальный номер каждой строки

# Типы данных в SQL

| Тип | Что хранит | Пример |
|-----|-----------|--------|
| `INT` | Целое число | ID: `42`, возраст: `28` |
| `VARCHAR(n)` | Строка до n символов | Имя: `'Алексей'` |
| `TEXT` | Длинный текст (без лимита) | Комментарий, описание |
| `BOOLEAN` | Истина / ложь | Активен: `true` |
| `DATE` | Дата | Дата рождения: `2000-03-15` |
| `DECIMAL(p,s)` | Дробное число | Цена: `10.99` |
| `TIMESTAMP` | Дата + время | Создан: `2024-01-15 14:30:00` |

<!--
Teacher Notes:
- Скажи про DECIMAL(p,s): p = всего цифр, s = после запятой. DECIMAL(10,2) = до 99999999.99
- Спроси по каждому типу: "Для чего ещё можно использовать?"
- ~5 мин

# VARCHAR vs TEXT — когда что использовать?

- **`VARCHAR(n)`** — строка с ограничением длины
  - Имя: `VARCHAR(100)` — имя не бывает длиннее 100 символов
  - Email: `VARCHAR(255)` — стандартный максимум
  - Используй когда знаешь максимальную длину

- **`TEXT`** — строка без ограничения
  - Комментарий пользователя
  - Описание товара
  - Биография профиля

> Правило: знаешь максимум → `VARCHAR`. Не знаешь → `TEXT`.

<!--
Teacher Notes:
- Частый вопрос: "Почему не всегда TEXT?" → VARCHAR быстрее индексируется
- Не углубляйся в индексы — скажи: "Так принято в профессии"
- ~3 мин

# CREATE TABLE — синтаксис

```sql
CREATE TABLE имя_таблицы (
    имя_столбца ТИП_ДАННЫХ,
    имя_столбца ТИП_ДАННЫХ,
    ...
);
```

- `CREATE TABLE` — команда создания
- Внутри скобок — список столбцов
- Каждый столбец: имя + тип через пробел
- Столбцы разделяются запятой
- В конце — `;`

<!--
Teacher Notes:
- Скажи: "Это как объявить класс — описываешь структуру, но не создаёшь ещё ни одного объекта"
- Обрати внимание на запятые — частая ошибка: забыть запятую или поставить после последнего столбца
- ~3 мин
-->

---

# CREATE TABLE users

```sql
CREATE TABLE users (
    id          INT,
    name        VARCHAR(100),
    email       VARCHAR(255),
    age         INT,
    is_active   BOOLEAN,
    created_at  DATE
);
```

- Таблица `users` — основа всего урока
- 6 столбцов с разными типами
- `is_active` — активен ли аккаунт
- `created_at` — дата регистрации

# CREATE TABLE orders

```sql
CREATE TABLE orders (
    id           INT,
```

# INSERT INTO — два варианта

**Вариант 1 — без имён столбцов (опасно):**

> Всегда используй вариант 2 — если порядок столбцов изменится, данные не перепутаются.

# SELECT WHERE — фильтрация

```sql
SELECT * FROM users WHERE is_active = true;
```

```sql
SELECT * FROM orders WHERE price > 500;
```

```sql
SELECT * FROM users WHERE age >= 25 AND is_active = true;
```

- `WHERE` — условие фильтрации
- `=`, `>`, `<`, `>=`, `<=` — операторы сравнения
- `AND` — оба условия должны быть истинны

# DELETE — удалить строку

```sql
DELETE FROM users WHERE id = 5;
```

- `DELETE FROM` — из какой таблицы удалять
- `WHERE` — условие (какие строки удалить)
- Удалённые строки восстановить **нельзя**

**DELETE vs DROP TABLE:**

| Команда | Что делает |
|---------|-----------|
| `DELETE FROM users WHERE id = 5` | Удаляет одну строку |
| `DELETE FROM users` | Удаляет все строки, таблица остаётся |
| `DROP TABLE users` | Удаляет всю таблицу целиком |

<!--
Teacher Notes:
- Скажи: "DELETE удаляет данные. DROP TABLE удаляет саму структуру — таблицу."
- ~4 мин
-->

# Итоги урока

> **Таблица** = класс из UML. **Строка** = объект. **Столбец** = атрибут.

> **Тип данных** определяет что хранить: `INT`, `VARCHAR`, `DECIMAL`, `BOOLEAN`, `DATE`, `TIMESTAMP`.

> **CREATE TABLE** создаёт структуру. **INSERT** заполняет. **SELECT** читает. **WHERE** фильтрует.

> **UPDATE** и **DELETE** без `WHERE` — меняют и удаляют **ВСЕ** строки. Всегда проверяй условие.

> **ALTER TABLE** — безопасно изменяет структуру без потери данных.

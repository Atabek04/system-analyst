# Pool и Lanes

**Pool** — рамка одного процесса/организации
**Lane** — роль внутри пула

- Pool — большой прямоугольник с подписью сбоку
- Lanes — горизонтальные полосы внутри пула
- Каждая задача лежит ровно в одной дорожке

**Правило:** Lane не описывает человека, она описывает **роль**. Один сотрудник может выполнять задачи из разных дорожек — но задача всегда принадлежит одной.

<!--
Teacher Notes:
- Pool в большинстве случаев один — "наша организация". Несколько Pool появляется, когда нужны внешние участники.
- Lanes — типичные роли: заявитель, регистратор, инспектор, кассир, экзаменатор
- ~3 мин
-->

---

# Pool «Мобильный ЦОН» с дорожками

```
┌──────────────────────────────────────────────┐
│ POOL: Мобильный ЦОН                          │
├──────────────────────────────────────────────┤
│ Lane: Заявитель      │ ○ → ▢ талон → ...    │
├──────────────────────┼──────────────────────┤
│ Lane: Регистратор    │ 👤 проверка док-в    │
├──────────────────────┼──────────────────────┤
│ Lane: Инспектор      │ ⚙ реестр водителей,  │
│                      │ 📤 Минздрав           │
├──────────────────────┼──────────────────────┤
│ Lane: Касса          │ ✋ приём пошлины       │
├──────────────────────┼──────────────────────┤
│ Lane: Экзаменатор    │ ▢ теория, площадка   │
├──────────────────────┼──────────────────────┤
│ Lane: Сотрудник выд. │ 👤 печать → выдача    │
└──────────────────────────────────────────────┘
```

> Каждая задача из прошлого урока переезжает в свою дорожку. Сама диаграмма не меняется — меняется её читаемость.

# Второй Pool + Message Flow

**Второй Pool** — внешняя организация, часто рисуется как "чёрный ящик" (без содержимого).

**Message Flow** — пунктирная стрелка с кружком на конце. Только она пересекает границы пулов.

**Правило:**
- Sequence Flow — сплошная, **только внутри одного пула**
- Message Flow — пунктирная, **только между пулами**
- Сплошная стрелка не пересекает границу пула. Никогда.

<!--
Teacher Notes:
- Это самое жёсткое правило BPMN. Запомнить раз и навсегда.
- Predict: тянут сплошную стрелку наружу — поправляй сразу
- ~3 мин
-->

---

# Пример: Мобильный ЦОН ↔ Минздрав

```
┌─ POOL: Мобильный ЦОН ────────────────┐
│  📤 Запрос в Минздрав ─ ─ ─ ─ ─ ┐    │
│       │                          ┊    │
│       ▼                          ┊    │
│  ○✉ Ответ получен ◀ ─ ─ ─ ─ ─ ─ ┊    │
└─────────────────────────────────┊────┘
                                  ┊  Message Flow
                                  ┊  (пунктир)
                                  ▼
┌─ POOL: Минздрав (чёрный ящик) ───────┐
│                                      │
└──────────────────────────────────────┘
```

> Чёрный ящик честно говорит: "что они там внутри делают — не наше дело".

# Sub-process (свёрнутый)

**Sub-process** — задача-папка, внутри которой свой собственный процесс

- Прямоугольник с символом `[+]` снизу
- На главной диаграмме — один блок
- Развернуть = открыть внутреннюю диаграмму

**Пример:**
```
... → [+] Сдача экзамена → ...
```

Внутри:
```
○ старт → ▢ Теория → ▢ Площадка → ▢ Город → ◉ конец
```

> Sub-process — это «зум-аут»: один прямоугольник снаружи, целая диаграмма внутри.

<!--
Teacher Notes:
- Подчеркни: внутри Sub-process работают все те же элементы — XOR, Timer, Tasks. Это полноценный процесс.
- Когда использовать: если фрагмент логически завершён и его можно объяснить отдельно
- ~3 мин
-->

# Loop marker

**Loop marker** — значок повтора снизу задачи или подпроцесса

- Круглая стрелка `↻` под прямоугольником
- Заменяет рисование явной обратной стрелки
- Условие повтора пишется рядом

**Пример:**
```
[+] Сдача экзамена ↻
       (повторяется до 3 попыток
        или до успеха)
```

> Маркер цикла говорит: «эта штука может повториться» — без визуального беспорядка.

<!--
Teacher Notes:

# Data Object

**Data Object** — артефакт, с которым работают задачи

- Иконка листа с загнутым углом: `📄`
- Соединяется с задачей пунктирной ассоциацией
- Не управляет потоком — сопровождает его
- Живёт только внутри одного экземпляра процесса

**Пример:**
```
        📄 Медсправка
              ┊
              ┊ ассоциация
              ▼
   📤 Запрос в Минздрав
```

> Data Object — это «вещь, которую задача читает или пишет».

<!--
Teacher Notes:
- Подчеркни: Data Object — это НЕ задача и НЕ событие. Это артефакт. Поток через него не идёт.
- ~3 мин
-->

# Data Store

**Data Store** — постоянное хранилище
- Иконка цилиндра: `🗄`
- Переживает экземпляр процесса (в отличие от Data Object)
- Используется для баз данных, реестров, систем хранения

**Пример в Мобильном ЦОН:**
- 🗄 АИС ЦОН — куда регистратор записывает дело
- 🗄 реестр водителей МВД — откуда инспектор читает сведения о лишении

> Data Object — одноразовая бумажка. Data Store — постоянная база.

<!--
Teacher Notes:
- Метафора: Data Object — это записка на стикере, Data Store — шкаф с папками
- ~2 мин
-->

# Group

**Group** — визуальная рамка, объединяющая логически связанные шаги

- Прямоугольник с пунктирным контуром (штрих-пунктир)
- Не влияет на исполнение
- Может пересекать дорожки

**Пример:**
Внутри Sub-process «Сдача экзамена» — рамка-группа «Экзаменационные испытания» вокруг блоков теория/площадка/город.

> Group — чисто косметика. Sub-process — функциональная единица.

<!--
Teacher Notes:
- Сравни с Sub-process: Sub-process — это "папка с диаграммой внутри"; Group — это просто визуальная рамка
- ~2 мин
-->

# Annotation

**Annotation** — комментарий для читателя

- Квадратная скобка с текстом: `[ ... ]`
- Соединяется ассоциацией
- Парсер процессов её игнорирует

**Пример:**
```
○⏱ 30 дней
   ┊
   ┊
[ "после 3 неудачных
   попыток подряд" ]
```

> Аннотация нужна там, где правило неочевидно из названия.

```
┌──── POOL: Мобильный ЦОН ────────────────────────────┐
│ Заявитель  : ○ → талон → ◇⌖(вызов/таймаут) → ...    │
│ Регистратор: 👤 проверка⚡→ ✋ ручная верификация    │
│ Инспектор  : ◇+ split → ⚙ реестр водителей          │
│                          📤 Минздрав                 │
│              → ◇+ join → ◇× «лишён?»                │
│              → ▲Signal → ◉● Terminate               │
│ Касса      : ✋ приём пошлины                        │
│ Экзаменатор: [+] Сдача экзамена ↻                   │
│              (внутри: OR, Timer 7/30/180 дн)        │
│ Выдача     : 👤 печать → 👤 выдача → ◉ ВУ выдано    │
└─────────────────────────────────────────────────────┘
       ┊ Message Flow
       ▼
┌──── POOL: МВД / Минздрав (чёрный ящик) ─────────────┐
└─────────────────────────────────────────────────────┘

Артефакты: 📄 Медсправка        📄 Личное дело
```

# Задание: процесс замены ВУ по истечении срока

**Условия:**
- Заявителю исполнилось 10 лет с даты выдачи ВУ — он пришёл менять
- Экзамены не нужны, нужны: медсправка + пошлина + фото
- Если медсправка просрочена → на медкомиссию (выходим за пределы ЦОН)
- База МВД проверяется автоматически параллельно с приёмом пошлины
- Если МВД вернул статус «лишён» → отказ + закрытие всех параллельных веток
- Замена ВУ хранится в АИС ЦОН

**Используй:** Pool + Lanes (минимум 4), второй Pool, Message Flow, AND, XOR, Signal или Terminate, Sub-process для «приём документов», Data Object «Личное дело», Data Store «АИС ЦОН».

# Разбор: что должно быть на диаграмме

**Минимальный чек-лист правильного решения:**

- ✓ Один Pool «Мобильный ЦОН» с дорожками: Заявитель / Регистратор / Инспектор / Касса
- ✓ Второй Pool «Минздрав» (или «Медкомиссия») как чёрный ящик
- ✓ Между пулами — только Message Flow (пунктир)
- ✓ AND-split + AND-join вокруг базы МВД и кассы
- ✓ XOR на «справка действительна?»
- ✓ XOR на «лишён?» → Signal → Terminate End
- ✓ Sub-process «Приём документов» с внутренней цепочкой
- ✓ Data Object «Личное дело» рядом с регистратором
- ✓ Data Store «АИС ЦОН» — ассоциация от Service Task

> Если все галочки стоят — твоя диаграмма читается любым аналитиком. Это и есть профессиональный BPMN.

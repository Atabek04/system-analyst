# Flashcard Generator — System Analyst

Generate Anki flashcards for the System Analyst Bootcamp using `Coding Questions` note type under the `System Analyst::` deck hierarchy.

## Before generating cards

Read these reference files:

1. **`references/syntax.md`** — note type, deck hierarchy, START/END format, file header
2. **`references/question-rules.md`** — question quality principles, templates, pitfalls
3. **`references/workflow.md`** — Obsidian → Anki sync process, folder structure

Also read the target flashcard file if it exists — check for duplicates before adding.

## Quick Reference

### Card Format

```
START
Coding Questions
{question}
Back: {answer}
Tags: {tags}
END
```

Multi-line answers: `Back:` on the question line, content below with bullets/bold.

### File Header

```markdown
TARGET DECK: System Analyst::{Category}::{Topic}
Tags: {default-tags}
**Related:** [[source note]]

---
```

### File Location

`05-Flashcards/{category}/{topic}.md` — one file per topic, matching the deck.

## Workflow

1. **Read the atomic note(s)** — never generate cards from general knowledge alone
2. **Read the references** listed above (especially first time)
3. **Read existing flashcard file** if it exists — avoid duplicates
4. **Extract questions** — ask: "What would I need to *retrieve* to explain this concept?"
5. **Write cards** following the format, one concept per card
6. **Quality check** — verify against `references/question-rules.md` checklist

## Key Rules

- **Language**: Russian for content, English IT terms stay in English
- **No `<!--ID: ...-->` lines** — auto-generated by Obsidian_to_Anki sync
- **Blank line** between `END` and next `START`
- **One concept per card** — if a note covers 3 ideas, make 3 cards
- **Don't skip important points** — every key concept, definition, or command becomes a card
- **No hints in questions** — the answer shouldn't be contained in the question
- **Audience**: interns with zero IT experience — keep language simple
